# Publishing A Static Showcase Site

`dioxus-showcase export` compiles the generated showcase app to WebAssembly and writes a
self-contained directory of static files. There is no server component: any host that can
serve files over HTTP can serve the result.

## The Command

```bash
dioxus-showcase export [--out-dir <DIR>] [--base-path <PATH>] [--debug]
```

| Flag | Default | Meaning |
| --- | --- | --- |
| `--out-dir` | `<build.out_dir>/site` | Directory the site is written to. |
| `--base-path` | `[build].base_path` from `DioxusShowcase.toml` | Public sub-path the site is served from. |
| `--debug` | off | Build unoptimized, with debug symbols, for faster iteration. |

What it does, in order:

1. Runs the same generation pass as `build`: rewrites `generated.rs` and `Dioxus.toml`,
   syncs assets, and writes `src/main.rs` only when absent. That file is write-once: an
   existing `main.rs` is never overwritten, so your edits to the generated app survive an
   export.
2. Clears the output directory (see [Output directory safety](#output-directory-safety)).
3. Runs `dx bundle --platform web --release` against the generated app crate.
4. Flattens the bundle into the output directory.
5. Writes `404.html` and `.nojekyll`, then prunes assets left over from earlier builds.

## What Gets Written

```
site/
├── .nojekyll                 # stops GitHub Pages from running Jekyll over the output
├── 404.html                  # copy of index.html; the SPA fallback for deep routes
├── index.html
└── assets/
    ├── <app>-<hash>.js       # wasm-bindgen glue
    ├── <app>_bg-<hash>.wasm  # the compiled showcase
    └── <name>-<hash>.css     # your stylesheets plus the showcase shell CSS
```

The browser tab title comes from `[project].name` in `DioxusShowcase.toml`.

### Why `404.html`

Story routes look like `/component/atoms-button`, but a static host has no such file on
disk. Every major static host serves `404.html` for unmatched paths, so the copy of
`index.html` boots the app, the Dioxus router reads the URL, and the requested story
renders. This is what makes a hard refresh or a shared deep link work.

Hosts that use a different fallback mechanism are covered below.

## Base Paths

If the site is served from anything other than the domain root, the base path must be set
so asset URLs and router links resolve. For a project GitHub Pages site at
`https://acme.github.io/design-system/`, the base path is `/design-system`.

Set it once in `DioxusShowcase.toml`:

```toml
[build]
out_dir = "target/showcase"
base_path = "/design-system"
```

or per invocation with `--base-path /design-system`. Leading and trailing slashes are
optional. A base path of `/` means "domain root" and is the default.

## Output Directory Safety

`export` clears its output directory before writing, so stale files never linger. To make
that safe it writes a `.dioxus-showcase-site` marker into every site it generates, and it
refuses to clear a non-empty directory that has no marker:

```
error: docs is not empty and was not generated by dioxus-showcase. Remove it or pass --out-dir <DIR>.
```

Point `--out-dir` at a directory dedicated to generated output, not at one that also holds
hand-written files.

## Deployment Recipes

### GitHub Pages

Commit this as `.github/workflows/showcase.yml`. It builds on every push to `main` and
publishes with the official Pages actions, so no `gh-pages` branch is needed.

```yaml
name: Showcase

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
        with:
          targets: wasm32-unknown-unknown
      - uses: Swatinem/rust-cache@v2
      - name: Install the Dioxus CLI
        run: cargo install dioxus-cli --locked
      - name: Install dioxus-showcase
        run: cargo install dioxus-showcase-cli --locked
      - name: Export the showcase
        # For a user or org site (acme.github.io) drop the --base-path flag.
        run: dioxus-showcase export --out-dir dist/showcase --base-path /${{ github.event.repository.name }}
      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist/showcase

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

Enable it once under *Settings → Pages → Build and deployment → Source: GitHub Actions*.

### Netlify

`netlify.toml`:

```toml
[build]
  command = "cargo install dioxus-cli dioxus-showcase-cli --locked && dioxus-showcase export --out-dir dist/showcase"
  publish = "dist/showcase"

[[redirects]]
  from = "/*"
  to = "/index.html"
  status = 200
```

The redirect rule is optional — the generated `404.html` already works — but a `200`
rewrite keeps the HTTP status correct for deep links.

### Vercel

`vercel.json`:

```json
{
  "buildCommand": "cargo install dioxus-cli dioxus-showcase-cli --locked && dioxus-showcase export --out-dir dist/showcase",
  "outputDirectory": "dist/showcase",
  "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
}
```

### Cloudflare Pages

Set the build command to
`cargo install dioxus-cli dioxus-showcase-cli --locked && dioxus-showcase export --out-dir dist/showcase`
and the output directory to `dist/showcase`. Add a `_redirects` file containing
`/* /index.html 200` if you want deep links to return `200` instead of `404`.

### Any Other Static Host

Upload the contents of the output directory. The only server-side requirement is the
common convention of serving `404.html` for unknown paths; without it the landing page
still works, but deep story links will not survive a refresh.

## Troubleshooting

**`failed to run dx bundle ... not found in PATH`**
Install the Dioxus CLI with `cargo install dioxus-cli --locked`, then confirm with
`dioxus-showcase doctor`, which reports the detected `dx` version.

**Blank page, console 404s on `/assets/...`**
The site is being served from a sub-path without a matching base path. Re-export with
`--base-path /<sub-path>`.

**The site loads and the shell renders, but there are no stories**
Check that the showcase app's `Cargo.toml` still carries `[profile.dev] lto = "thin"` and
`[profile.release] lto = true`. On `wasm32-unknown-unknown` those are required for
correctness, not speed: without them the linker never pulls your component crate out of its
rlib and every story registration is dropped, producing an empty showcase with no error
anywhere. `dioxus-showcase check` warns if either is missing, and the README explains the
mechanism in full. Restore them and re-export.

**A deep link works in the app but 404s on refresh**
The host is not falling back to `404.html`. Add the redirect rule for your host from the
recipes above.

**The wasm binary is larger than expected**
Use the default release mode; `--debug` keeps debug symbols and skips optimization.
